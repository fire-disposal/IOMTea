# 后端 + Web 改进方案（基于代码现状）

> 日期：2026-05-15
> 目标场景：居家健康监控（非临床护士站）

## 1. 现状结论（从代码出发）
- 权限体系“有种子、无执行”：权限种子已存在，但未在路由层做授权校验。
- 数据域缺少“家庭/监护关系”建模：患者与家庭成员、看护人、设备的关系未落地。
- 业务闭环缺失：告警、用药、随访、设备运维没有统一闭环链路。
- Web 实时订阅无鉴权，且角色视图不分离。
- 代码与文档不一致：文档中存在的地图配置能力在代码中缺失。

## 2. 关键问题清单（含代码依据）
### P0 级
1) **实时订阅无鉴权/无权限过滤**
   - 服务端 WebSocket 未校验 token 与访问范围，客户端连接也未携带凭证。
   - 影响：任何登录用户可订阅任意患者/地图数据。

2) **权限与角色未落地**
   - auth 中间件仅解析 token，不进行资源授权。
   - 影响：角色与权限形同虚设，无法支撑家庭成员/看护人/机构角色区分。

### P1 级
3) **领域模型缺失（家庭/监护关系）**
   - 患者、设备、用户三者关系仅依赖 patientId 绑定，缺少家庭/监护/授权模型。
   - 影响：无法完成居家场景的“家庭关系与授权”闭环。

4) **闭环流程缺失（告警/用药/随访）**
   - 告警仅有状态切换；用药与随访均缺乏关联处置链路与责任人。
   - 影响：演示任务无法完成，无法产生“可追踪结果”。

5) **文档与代码不一致**
   - 文档中标注的 mapConfig 能力未在代码中发现。
   - 影响：规划与实现脱节，导致评估误判与演示失败。

## 3. 改进方案（按阶段）

### 阶段 A：安全与闭环底座（1-2 周）
- **WebSocket 鉴权与授权**
  - 连接必须携带 token，服务端校验并限制 ward/map 订阅范围。
- **引入最小授权检查**
  - 在 tRPC 路由层引入 `requirePermission` 校验（基于 `userRole`）。
- **补齐告警处置轨迹**
  - 记录确认/解决的操作者与时间（审计字段）。

### 阶段 B：居家场景模型落地（2-4 周）
- **家庭/监护关系建模**
  - 新增 Household、Caregiver、FamilyMember 关系表或桥接表。
  - 支持“家庭成员授权访问”与“设备归属/共享”规则。
- **患者-设备-家庭统一入口**
  - 形成“家庭视图”页面，支持患者与设备的绑定、解除与共享。

### 阶段 C：业务闭环完善（2-4 周）
- **告警闭环**：指派 → 确认 → 处理 → 复盘（简化状态机）。
- **用药闭环**：医嘱/计划 → 执行 → 漏服提醒 → 复盘。
- **随访闭环**：预约 → 到访 → 记录 → 反馈。

### 阶段 D：Web 信息架构重构（2-3 周）
- **角色视图拆分**：家庭成员视图 / 看护人视图 / 机构管理员视图。
- **统一任务入口**：围绕“待办/告警/随访/用药”组织主导航。
- **建立可演示路径**：从“家庭绑定→设备入户→监测→异常提醒→远程处置”的主线。

## 4. 建议的验收标准（简版）
- 角色最小权限控制生效（无法越权订阅或查看不属于家庭的数据）。
- 具备 1 条完整的“居家健康闭环演示路径”。
- 告警处置链路可追溯（责任人/时间/结果）。
