# 节点图谱管理器设计文档

**日期**：2026-05-19
**状态**：已确认

---

## 概述

以 React Flow 为核心构建用户级节点化图谱管理系统，替换现有 DeviceListPage，统一管理用户管辖范围内的房间、设备(PIN)、患者及其关系。房间拓扑为图谱骨架，设备与患者作为子节点挂载于房间之上。

---

## 数据模型

### 图谱层次

```
基础层：房间拓扑图
  [客厅] —— [走廊] —— [卧室]
    │         │         │
  [厨房]   [卫生间]   [次卧]

挂载层：
  - 设备 → 房间（IoT 设备部署于某房间）
  - 设备 → 用户（随身设备，不限定房间）
  - 患者 → 房间（患者当前所在房间）
```

### 节点类型

| 类型 | 数据来源 | 视觉形式 |
|------|---------|---------|
| 房间 (Room) | home-graph / patient.tags.homeGraph | 矩形主容器节点，显示名称 + 设备数 + 患者数 |
| 设备 (PIN) | users_pin / devices 表 | 小型子节点卡片，嵌入房间内部 |
| 患者 (Patient) | patients 表 | 小型子节点卡片，嵌入房间内部 |

### 连线语义

| 关系 | 方向 | 含义 |
|------|------|------|
| 相邻 (adjacent) | Room ↔ Room | 房间物理连通 |

设备与患者不参与拓扑连线，通过嵌套归属表达关系。

## 后端扩展

### `node-graph` 子路由（扩展 home-graph router）

| 端点 | 说明 |
|------|------|
| `getGraph` | 加载用户图谱（房间坐标 + 连线 + 子节点布局） |
| `saveGraph` | 保存布局元数据（位置/排列，不复制业务数据） |

房间、设备、患者数据实时从原表读取，图谱表仅存布局元数据（节点坐标、房间内子节点排列顺序）。

已有 `pin.bindRoom` API 可复用，无需新增绑定端点。

## 前端设计

### 新增文件

```
apps/web/src/pages/NodeGraphPage.tsx          — 主画布页
apps/web/src/components/graph/
  ├── RoomNode.tsx                             — 房间主节点（可伸缩容器）
  ├── DeviceSubNode.tsx                        — 设备子节点卡片
  ├── PatientSubNode.tsx                       — 患者子节点卡片
  ├── NodePanel.tsx                            — 右侧面板（未分配设备/患者列表）
  ├── ContextMenu.tsx                          — 右键菜单
  └── GraphToolbar.tsx                         — 工具栏（撤销、自动布局、搜索）
```

### 设备自描述信息

设备子节点展示从 PIN/device 表实时查询的自我描述：

| 字段 | 来源 |
|------|------|
| 类型图标 + 名称 | `device.deviceType`, PIN label |
| 在线状态 | `device.status`, `device.lastSeenAt` |
| 最新体征值 | `events` 表最新 observation |
| 绑定患者 | `device.patientId` 关联 |

### 交互清单

- 画布拖拽创建房间节点
- 从右侧面板拖拽设备/患者到房间完成绑定
- 房间之间拖拽连线建立相邻关系
- 设备子节点可在房间内拖拽重排、跨房间拖拽解绑/重绑
- 右键菜单：编辑房间、连接房间、解除绑定、删除、查看详情
- 连线交互：点击选中编辑、拖拽创建、双击删除
- 工具栏：撤销/重做、自动布局（力导向）、搜索定位、缩放适配
